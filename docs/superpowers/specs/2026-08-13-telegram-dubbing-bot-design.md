# Telegram-бот для дубляжа видео RU → Bahasa Indonesia

Дата: 2026-08-13

## Задача

Кидаешь боту видео, где говоришь по-русски, — получаешь обратно тот же ролик, где
говоришь на индонезийском. Дубляж через ElevenLabs Dubbing API.

## Проверено на живом API

Пайплайн прогнан целиком до написания спеки (ключ free-тарифа, тестовый ролик 10 сек):

| Шаг | Результат |
| --- | --- |
| `POST /v1/dubbing` с `source_url` на произвольную прямую ссылку | Работает, вернул `dubbing_id` |
| `GET /v1/dubbing/{id}` | `status: "dubbed"`, `model: "dubbing_v1"` |
| `GET /v1/dubbing/{id}/audio/id` | `video/mp4`, 802 КБ |
| Расход | 334 кредита за ~10 сек → **≈2000 кредитов на минуту** |

Из этого следует главное: **файл не нужно гонять через функцию Vercel** — достаточно
дать ElevenLabs публичную ссылку, и он скачает сам.

## Ограничения, вокруг которых построен дизайн

1. **Telegram Bot API: скачивание ≤ 20 МБ, отправка ≤ 50 МБ.** Обойти нельзя.
   Реальные ролики — 400 МБ (проверено на `IMG_3418.MOV`, 398,8 МБ с iPhone).
   Поэтому видео попадает в систему не через бота, а через страницу загрузки.
   Отдельно: отправка **по HTTP-ссылке ограничена 20 МБ** («5 MB max size for photos
   and 20 MB max for other types of content»), полные 50 МБ доступны только при
   загрузке файла через `multipart/form-data` с нашей стороны. Отсюда три способа
   доставки результата, а не два.
2. **Вебхука о завершении дубляжа у ElevenLabs нет** — только опрос статуса.
3. **Минутный cron на Vercel Hobby недоступен** (аккаунт личный, существующие
   cron-задачи в репо — суточные и месячные). Опрос строится без cron.
4. **Лимит выполнения функции — 300 с**, а дубляж длится дольше.
5. **Free-тариф ElevenLabs:** дубляж только с водяным знаком
   (`watermark=false` → `403 subscription_required`), 10 000 кредитов ≈ 5 минут в месяц.

## Архитектура

Новый Vercel-проект из папки `dub-bot/` этого репозитория — по образцу `ig-dm-bot/`.
Отдельный бот и отдельный токен, чтобы не смешивать с отчётным ботом `qurany`.

Стек: Next.js 16 App Router + TypeScript + `@vercel/blob`. Next нужен из-за
страницы загрузки; на голых функциях её не сделать.

### Поток

```
/dub в боте
   └─> бот отдаёт ссылку …/u/<token>   (HMAC, живёт 30 мин, привязан к chat_id)

страница /u/<token>
   ├─ выбираешь видео из галереи
   ├─ читаем длительность прямо из файла (<video>.duration), показываем оценку:
   │  «3:12 ≈ 6400 кредитов, у тебя осталось 9666»
   ├─ жмёшь «Дублировать»
   └─ браузер грузит файл НАПРЯМУЮ в Vercel Blob (@vercel/blob/client, multipart)
      — функция файла не видит, лимитов по размеру нет

POST /api/dub/start
   ├─ проверяет токен и остаток кредитов
   ├─ POST /v1/dubbing { source_url: <blob>, source_lang: ru, target_lang: id }
   ├─ пишет задачу в Blob: dub/jobs/<jobId>.json
   └─ отвечает в TG «взял в работу» и запускает первый tick

GET /api/dub/tick?job=…
   ├─ опрашивает ElevenLabs каждые 10 с, живёт до ~240 с
   ├─ не готово → вызывает сам себя и выходит (обход лимита 300 с без cron)
   └─ dubbed → если до конца бюджета меньше 2 минут, откладывает доставку
                на свежий вызов: заливка и отправка 50 МБ в остаток бюджета
                не укладываются
              → помечает задачу статусом delivering, чтобы вторая цепочка
                (например, после /status) не отправила тот же ролик дважды
              → стримит MP4 из ElevenLabs в Blob
              → шлёт в TG по размеру результата:
                  ≤20 МБ  — sendVideo с Blob-ссылкой (Telegram качает сам)
                  ≤50 МБ  — sendVideo загрузкой multipart через нашу функцию
                  >50 МБ  — сообщение со ссылкой на Blob
              → удаляет исходник
```

Вкладку после запуска можно закрыть: задачу доводит серверная цепочка, а не браузер.

### Состояние задачи

`dub/jobs/<jobId>.json`:

```json
{
  "jobId": "…", "chatId": 123, "dubbingId": "…",
  "sourceUrl": "…", "resultUrl": null,
  "status": "pending | dubbing | delivering | done | failed",
  "durationSec": 192, "createdAt": "…",
  "deliveringAt": null, "error": null
}
```

`delivering` — не блокировка: Blob не умеет compare-and-set. Это лишь узкое окно
плюс правило перехвата — если `deliveringAt` старше пяти минут, значит вызов,
который взялся доставлять, умер, и задачу можно забрать. Без перехвата упавшая
доставка запирала бы задачу навсегда.

Токены загрузки — HMAC от `chatId` и срока годности, без хранения в Blob.

### Водяной знак

Не хардкодится. `/api/dub/start` читает `/v1/user/subscription` и ставит
`watermark: tier === "free"`. Апгрейд тарифа снимает знак сам, править код не нужно.

## Обработка ошибок

- `status: "failed"` от ElevenLabs → текст ошибки в Telegram, задача закрывается.
- Задача старше 30 минут → сдаёмся, пишем в Telegram, чтобы не крутить цепочку вечно.
- Не хватает кредитов на оценку → отказ до создания задачи, с цифрами в ответе.
- Оборвалась цепочка tick → `/status` в боте подхватывает и добивает задачу вручную.
- Повторный `/dub` при активной задаче не ломает текущую: у каждой свой `jobId`.

## Безопасность

Страница загрузки публична, а дубляж стоит денег, поэтому:

- whitelist `chat_id` в вебхуке;
- `secret_token` в заголовке вебхука Telegram;
- HMAC-токены со сроком 30 минут на страницу загрузки;
- исходник в Blob удаляется сразу после успешного дубляжа;
- ключ ElevenLabs, засветившийся в переписке, перевыпускается после настройки env.

## Переменные окружения

`TELEGRAM_DUB_BOT_TOKEN`, `TELEGRAM_ALLOWED_CHAT_IDS`, `TELEGRAM_WEBHOOK_SECRET`,
`ELEVENLABS_API_KEY`, `DUB_TOKEN_SECRET`, `BLOB_READ_WRITE_TOKEN` (даёт Vercel).

## Тестирование

Vitest, как в основном репо:

- `estimateCredits(durationSec)` — округление, граница нуля;
- `pickDelivery(sizeBytes)` — три ветки доставки на границах 20 МБ и 50 МБ;
- `signToken` / `verifyToken` — валидный, просроченный, подделанный, чужой chat_id;
- разбор ответа статуса: `dubbed`, `dubbing`, `failed`;
- роутер команд бота.

Ручной смоук: ролик 15 секунд с русской речью, до конца цепочки.

## Что осталось проверить на реальном ролике

`can_use_instant_voice_cloning: false` на free-тарифе. Клонирование голоса внутри
дубляжа может быть частью пайплайна и работать всё равно — по документации
однозначного ответа нет. Проверяется первым же смоук-тестом: если голос в ответе
чужой, вопрос закрывается апгрейдом до Starter.

## Вне рамок

Липсинк (у ElevenLabs это отдельная опция Studio, базовый дубляж губы не двигает),
несколько целевых языков за раз, ручная правка перевода, работа на несколько
пользователей, хранение истории роликов.
