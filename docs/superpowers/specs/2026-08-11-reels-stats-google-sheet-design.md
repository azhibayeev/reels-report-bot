# Таблица статистики Reels в Google Sheets

Дата: 2026-08-11
Статус: утверждено пользователем

## Задача

Вся лента Reels аккаунта **@daristeppe** (IG business id `17841413773053161`) должна
лежать в Google-таблице: строка = ролик, колонки = статистика. Таблица живая —
обновляется автоматически, вручную ничего импортировать не нужно.

Транскрибация речи/текста с видео рассматривалась и **исключена из объёма** по
решению пользователя.

## Источник данных

Instagram Graph API (`graph.instagram.com`) от имени самого аккаунта. Токен уже
есть в проекте: env `IG_ACCESS_TOKEN` + автопродление через `lib/token.ts`
(`resolveToken()`). Скрейпинг не нужен и не используется.

Два запроса на прогон:

1. `GET /{ig_user_id}/media?fields=id,media_product_type,permalink,timestamp,caption,like_count,comments_count&limit=100`
   — постранично до конца, оставляем `media_product_type === "REELS"`.
2. На каждый рилс `GET /{media_id}/insights?metric=views,reach,shares,saved,total_interactions,ig_reels_avg_watch_time`
   — параллельно, конкурентность 10 (как `fetchViews` в `lib/instagram.ts`).

**Деградация обязательна.** У части старых роликов отдельные метрики
недоступны (API отвечает ошибкой на весь запрос, если хотя бы одна метрика
не поддержана). Поэтому: при ошибке пакетного запроса делаем повторную попытку
базовым набором `views,reach,total_interactions`; если и она падает — строка
всё равно попадает в таблицу с пустыми ячейками метрик. Один плохой ролик
никогда не роняет прогон.

Лайки и комментарии берём из полей медиа (`like_count`, `comments_count`) —
они есть всегда; одноимённые метрики insights используем только как запасной
вариант.

## Состав таблицы

Один лист (по умолчанию `Reels`). Сортировка по дате публикации, новые сверху.

| Колонка | Источник |
|---|---|
| № | порядковый номер строки |
| Дата | `timestamp` → формат `ДД.ММ.ГГГГ ЧЧ:ММ`, таймзона Asia/Jakarta |
| Ссылка | `permalink` |
| Начало подписи | `caption`, первые 120 символов, переводы строк → пробел |
| Просмотры | insights `views` |
| Охват | insights `reach` |
| Лайки | медиа `like_count` |
| Комментарии | медиа `comments_count` |
| Репосты | insights `shares` |
| Сохранения | insights `saved` |
| Всего реакций | insights `total_interactions` |
| ER % | всего реакций ÷ охват × 100, 2 знака; пусто при охвате 0 |
| Ср. досмотр, с | `ig_reels_avg_watch_time` (мс) ÷ 1000, 1 знак |
| ID | `media_id` |

Строка 1 — заголовки, закреплена. В ячейке справа от заголовков — время
последнего обновления.

Запись **идемпотентна**: каждый прогон переписывает диапазон целиком и очищает
хвост от предыдущего (более длинного) прогона. Дублей и рассинхрона быть не может.

## Архитектура

Новые модули, стиль — как у существующих (`lib/chart.ts`, `lib/monitor.ts`):
чистая логика отдельно от сети, без новых npm-зависимостей.

### `lib/sheets.ts`

Минимальный клиент Google Sheets API v4 на service account.

- `getAccessToken()` — собирает JWT (`RS256`) через встроенный `node:crypto`
  (`createSign("RSA-SHA256")`), меняет его на access token в
  `https://oauth2.googleapis.com/token` (grant `urn:ietf:params:oauth:grant-type:jwt-bearer`),
  scope `https://www.googleapis.com/auth/spreadsheets`. Токен живёт час,
  кэшируется в памяти модуля.
- `writeSheet(spreadsheetId, tab, values)` — `values.update` диапазона
  `A1` с `valueInputOption=RAW`, затем `values.clear` хвоста, если предыдущий
  прогон был длиннее.
- `freezeHeader(spreadsheetId, tab)` — `batchUpdate` с `updateSheetProperties`,
  вызывается только когда лист создаётся/шапка ставится впервые.

Приватный ключ приходит из env одной строкой с `\n` — разворачиваем перед
подписью.

### `lib/reels-table.ts`

- `ReelRow` — типизированная строка.
- `buildRows(media, insights)` — чистая: соединяет медиа и инсайты, считает
  ER %, сортирует по дате убыв. Тестируется без сети.
- `toSheetValues(rows, updatedAt)` — чистая: заголовки + матрица значений для
  Sheets. Числа отдаются числами (чтобы в таблице считались), пустые — `""`.
- `fetchReelInsights(token, ids)` — сеть: конкурентность 10 + деградация,
  описанная выше.
- `fetchAllReelsDetailed(igUserId, token)` — сеть: пагинация медиа с
  расширенным набором полей.

### `app/api/sheet/route.ts`

`GET`, авторизация `Bearer CRON_SECRET` (как `/api/report` и `/api/monitor`).
`maxDuration = 300`.

- без параметров — собирает данные и пишет в таблицу, отвечает
  `{ ok, reels, updatedAt }`;
- `?dry=1` — собирает и возвращает первые строки в JSON, **не** трогая таблицу.

### Интеграция в ежедневный крон

В `app/api/report/route.ts` после отправки отчёта — ещё один изолированный
`try/catch` (по образцу блоков кликов/таргета/графика), который синхронизирует
таблицу. Новый job на cron-job.org заводить не нужно: существующий вызов
`/api/report` в 12:30 по Джакарте обновит и лист. Ошибка Sheets не роняет
Telegram-отчёт, только пишется в лог.

## Конфигурация (env в Vercel prod)

| Переменная | Смысл |
|---|---|
| `GOOGLE_SA_EMAIL` | e-mail service account |
| `GOOGLE_SA_PRIVATE_KEY` | приватный ключ из JSON-ключа (PEM, `\n` экранированы) |
| `SHEETS_SPREADSHEET_ID` | id таблицы из её URL |
| `SHEETS_TAB` | имя листа, по умолчанию `Reels` |

Если `SHEETS_SPREADSHEET_ID` не задан — блок синхронизации тихо пропускается,
как и FB-часть монитора без своих env.

## Ручные шаги пользователя (однократно)

1. Создать пустую Google-таблицу, скопировать её ссылку.
2. Google Cloud Console: новый проект → включить Google Sheets API → создать
   service account → создать JSON-ключ и скачать.
3. Расшарить таблицу на e-mail service account с ролью «Редактор».
4. Передать JSON-ключ и ссылку — они уходят в env Vercel.

## Тесты (vitest)

`tests/reels-table.test.ts` — чистые функции:
- `buildRows` считает ER %, ставит пусто при нулевом охвате, сортирует по дате убыв.;
- `buildRows` не падает, когда инсайтов по ролику нет вовсе;
- `toSheetValues` отдаёт заголовок + числа числами и правильную длину строк;
- обрезка подписи до 120 символов и схлопывание переводов строк.

`tests/sheets.test.ts` — сборка JWT-claim (без реальной подписи и сети):
корректные `iss`, `scope`, `aud`, `exp`.

Сетевые функции тестами не покрываются — как и в остальном проекте.

## Проверка после деплоя

1. `curl -H "Authorization: Bearer $(cat .superpowers/cron-secret.txt)" "https://qurany-eight.vercel.app/api/sheet?dry=1"`
   — убедиться, что данные собираются и метрики не пустые.
2. Тот же запрос без `?dry=1` — таблица заполняется.
3. Глазами проверить лист: число строк совпадает с числом рилсов, репосты и
   сохранения не нулевые повсеместно.

## Что осознанно не делаем

- Историю по дням (вторая вкладка) — пользователь выбрал одну вкладку с итогами.
- Второй аккаунт (`qurany_app`) — только @daristeppe.
- Транскрибацию видео.
- Графики и условное форматирование внутри таблицы — пользователь сделает сам
  средствами Google Sheets поверх данных.
