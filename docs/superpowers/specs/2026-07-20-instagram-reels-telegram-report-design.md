# Дизайн: ежедневный Telegram-отчёт по просмотрам Instagram Reels

Дата: 2026-07-20
Статус: утверждён пользователем

## Цель

Каждый день в 12:30 по Джакарте (WIB, UTC+7) присылать в групповой Telegram-чат
отчёт по Instagram-странице (Business/Creator аккаунт):

- прирост просмотров каждого рилса за последние 24 часа (окно: вчера 12:30 WIB → сегодня 12:30 WIB);
- сколько новых рилсов вышло за это окно;
- итоговые цифры и топ-10, полная таблица — CSV-файлом.

Язык отчёта — русский.

## Архитектура

Проект на Vercel (бесплатный тариф), TypeScript, Next.js App Router.

- **Vercel Cron**: `30 5 * * *` UTC (= 12:30 WIB) вызывает `GET /api/report`.
- **Instagram Graph API** («Instagram API with Instagram Login», Facebook-страница не нужна):
  - список всех медиа с пагинацией, фильтр `media_product_type=REELS`;
  - просмотры каждого рилса через insights (метрика `views`), запросы батчами
    (Graph API batch, до 50 запросов на вызов), чтобы выдержать лимиты при сотнях рилсов;
  - долгоживущий токен (60 дней) автоматически продлевается при каждом запуске
    через `refresh_access_token`; обновлённый токен сохраняется в Blob.
- **Vercel Blob** — хранилище:
  - `snapshots/YYYY-MM-DD.json` — снимок дня: timestamp снятия + по каждому рилсу
    `{id, permalink, published_at, views}`;
  - `state/token.json` — актуальный IG-токен после продления.
- **Telegram Bot API**: `sendMessage` (HTML-разметка) + `sendDocument` (CSV) в групповой чат.

## Логика расчёта

1. Снять текущий снимок всех рилсов, сохранить в Blob.
2. Найти последний предыдущий снимок (обычно вчерашний).
3. Прирост рилса = `views_сегодня − views_в_предыдущем_снимке`.
   Рилс, отсутствующий в предыдущем снимке, — новый: прирост = все его просмотры.
4. Новые рилсы за окно определяются по времени публикации (`timestamp` медиа)
   в интервале между предыдущим снимком и текущим.
5. Суммарный прирост = сумма приростов по всем рилсам.

## Формат отчёта

Сообщение 1 (HTML):

- заголовок с датой и фактическим периодом отчёта;
- 📊 суммарный прирост просмотров за сутки;
- 🆕 число новых рилсов + ссылка и просмотры каждого;
- 🏆 топ-10 рилсов по приросту: ссылка, прирост, всего просмотров.

Сообщение 2: CSV-файл `reels-YYYY-MM-DD.csv` со столбцами:
ссылка, дата публикации, просмотров всего, прирост за сутки.

## Крайние случаи и ошибки

- **Первый запуск** (нет предыдущего снимка): отчёт с текущими суммарными цифрами
  и пометкой «базовый замер, прирост появится завтра».
- **Пропущенный день**: прирост считается от последнего доступного снимка,
  в отчёте указывается фактический период.
- **Ошибка Instagram API / Telegram API**: функция шлёт в тот же чат короткое
  сообщение об ошибке (если Telegram доступен), ошибка видна в логах Vercel.
- **Истёкший IG-токен**: сообщение в чат с просьбой перевыпустить токен.
- **Защита эндпоинта**: `/api/report` принимает запрос только с заголовком
  `Authorization: Bearer ${CRON_SECRET}` (Vercel Cron подставляет его сам).

## Переменные окружения

- `IG_ACCESS_TOKEN` — стартовый долгоживущий токен Instagram (дальше продлевается сам);
- `IG_USER_ID` — ID Instagram-аккаунта;
- `TELEGRAM_BOT_TOKEN` — токен бота (@BotFather, уже есть у пользователя);
- `TELEGRAM_CHAT_ID` — ID группового чата;
- `CRON_SECRET` — секрет для защиты эндпоинта;
- `BLOB_READ_WRITE_TOKEN` — выдаётся Vercel Blob автоматически.

## Тестирование

- Unit-тесты чистой логики: расчёт приростов, определение новых рилсов,
  форматирование сообщения и CSV (Vitest).
- Интеграция с внешними API проверяется вручную тестовым запуском
  `/api/report` после подстановки реальных токенов.

## Вне рамок (YAGNI)

- Никаких команд боту (/stats и т.п.) — только ежедневная рассылка.
- Никаких других метрик (лайки, охваты, подписчики) — только просмотры рилсов.
- Никакой базы данных — достаточно JSON-снимков в Blob.

## Что понадобится от пользователя после написания кода

1. Создать приложение в Meta for Developers и получить долгоживущий токен
   (будет пошаговая инструкция в `SETUP.md`).
2. Добавить бота в групповой чат и узнать ID чата (инструкция там же).
3. Токен Telegram-бота.
