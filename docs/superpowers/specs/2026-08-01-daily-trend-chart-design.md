# Дизайн: график динамики (просмотры + клики) в ежедневном отчёте

Дата: 2026-08-01
Статус: одобрен пользователем, готов к плану реализации

## Цель

Ежедневный Telegram-бот дополнительно присылает **картинку-график**, по которой визуально видно, движемся ли мы вверх или вниз по двум ключевым показателям: **просмотры рилсов** и **заходы по ссылкам (клики)**. Пользователь — нетехнический менеджер; ценность — одним взглядом понять направление тренда.

## Решения (согласованы с пользователем)

- **Метрика — прирост «за день»**, а не накопленный тотал. Накопленный тотал почти всегда только растёт и направление тренда не показывает; дневной прирост скачет вверх/вниз и отражает импульс.
- **Один график, две линии, две шкалы Y.** Просмотры — десятки тысяч, клики — десятки; на одной шкале клики были бы невидимы. Левая ось — просмотры, правая — клики.
- **Окно — 14 дней.**
- **Доставка — только в ежедневном отчёте**, в тему «Daily» (та же тема, что текстовый отчёт и сводка кликов; env `TELEGRAM_THREAD_ID`).
- **Рендер картинки — внешний сервис QuickChart** (отдаёт PNG по конфигу Chart.js). Причина: не требует тяжёлых графических зависимостей (canvas/chartjs-node-canvas капризны на Vercel). Альтернатива (серверный рендер) отклонена.

## Что видит пользователь

Одно фото в теме Daily, сразу под текстовым отчётом. Подпись: «📈 Динамика за 14 дней».
- Линия **«Просмотры за день»** — сумма прироста просмотров всех рилсов за сутки (левая шкала).
- Линия **«Заходы за день»** — уникальные люди, зашедшие по ссылкам за сутки (правая шкала).
- Ось X — даты в формате дд.мм.

## Источники данных

### Просмотры за день
- Ежедневные снапшоты в Vercel Blob (`snapshots/YYYY-MM-DD.json`), каждый содержит `reels[]` с `views` → тотал = сумма `views`.
- Серия: взять последние ~15 снапшотов, отсортировать по дате-ключу, посчитать дневной прирост `total[d] − total[d−1]` → до 14 точек.
- Если пропущен день (нет снапшота) — точки за этот день просто нет (разрыв), прирост считается между соседними доступными снапшотами. Меньше 2 снапшотов → серию построить нельзя.

### Заходы за день
- Новый запрос в PostHog (HogQL): уникальные `person_id` события `$pageview` по календарным дням за последние 14 дней.
  - `SELECT toDate(timestamp) AS d, uniq(person_id) AS u FROM events WHERE event = '$pageview' AND timestamp >= toDateTime(<epoch 14 дней назад>) GROUP BY d ORDER BY d`.
- Бакет по календарному дню (`toDate`), а не по границе спринта 12:30 — для формы тренда допустимо; это осознанное упрощение, зафиксировано здесь.
- **Важно (глюк проекта):** фильтр по property в `WHERE` отдаёт `results:null`. Здесь `WHERE` держит только `event` + `timestamp`, а `toDate`/`uniq` — не property-фильтры, поэтому запрос безопасен.

## Компоненты (изоляция и границы)

| Модуль | Что делает | Вход → Выход |
|---|---|---|
| `lib/storage.ts` (+функция) | Читает серию снапшотов за N дней | `loadRecentSnapshots(limit)` → `Snapshot[]` (по возрастанию даты) |
| `lib/posthog.ts` (+функция) | Заходы по дням | `getDailyClicks(sinceEpoch)` → `{ date: string; uniq: number }[]` |
| `lib/chart.ts` (**новый**) | Строит конфиг Chart.js и получает PNG | `buildTrendChart(views, clicks)` → config; `renderChartPng(config)` → `Buffer` |
| `lib/telegram.ts` (+функция) | Загрузка фото в Telegram | `sendPhoto(png, caption?, opts?)` (multipart, как `sendDocument`) |
| `app/api/report/route.ts` | Точка вызова после блока кликов | изолированный `try/catch` |

### `lib/chart.ts` — детали
- `buildTrendChart(viewsSeries, clicksSeries)`:
  - Общая ось X = объединение дат обеих серий, отсортированная; формат метки дд.мм.
  - Dataset 1: «Просмотры за день», `yAxisID: 'y'` (левая ось).
  - Dataset 2: «Заходы за день», `yAxisID: 'y1'` (правая ось, `grid.drawOnChartArea:false`).
  - Тип `line`, точки видимые, подписи по-русски, светлый фон.
- `renderChartPng(config)`:
  - `POST https://quickchart.io/chart` с телом `{ chart: config, width, height, backgroundColor, format: 'png', devicePixelRatio: 2 }`.
  - Ответ — бинарный PNG → вернуть `Buffer`. Ошибка/не-200 → бросить (ловится вызывающим).

### `lib/telegram.ts` — `sendPhoto`
- По образцу `sendDocument`: `FormData` с `chat_id`, опциональным `message_thread_id`, `caption` (parse_mode HTML), `photo` как `Blob` PNG. Метод `sendPhoto`.

## Поток данных

```
cron → GET /api/report
  ├─ (как сейчас) снапшот, отчёт по рилсам → sendMessage (Daily)
  ├─ (как сейчас) клики за сутки → sendMessage (Daily)
  └─ [НОВОЕ, свой try/catch]
       loadRecentSnapshots(15) → серия просмотров/день
       getDailyClicks(14д)      → серия заходов/день
       buildTrendChart(...)     → конфиг
       renderChartPng(...)      → PNG
       sendPhoto(PNG, "📈 Динамика за 14 дней") → Daily
```

## Обработка ошибок

- Весь блок графика — в **отдельном `try/catch`**; при любой ошибке (QuickChart недоступен, PostHog, мало данных) — `console.error` и продолжаем. Текстовый отчёт и клики уже отправлены и не страдают.
- Меньше 2 снапшотов или пустые серии → график пропускается тихо (лог).

## Проверка

- Ручной прогон на проде: `GET /api/report?force=1` с `Authorization: Bearer <CRON_SECRET>` → подтвердить, что фото-график появилось в теме Daily и линии осмысленны (данных за ~12 дней достаточно).
- Отдельно быстрый локальный тест `renderChartPng` на фейковой серии (PNG не пустой, статус 200) — опционально.

## Вне рамок (YAGNI)

- Линия подписчиков на графике — не добавляем (пользователь не просил).
- Команда `/grafik` по запросу — не в этой итерации (выбрана доставка только в ежедневном отчёте).
- Отдельная тема «Аналитика» — не используется (всё в Daily).
