# Настройка бота Reels Report

Следуйте шагам ниже по порядку. Каждый шаг пронумерован и содержит точные пути по интерфейсу и команды для копирования.

---

## Шаг 1. Получение Instagram-токена и User ID

### 1.1. Создать приложение на Facebook Developers

1. Откройте браузер и перейдите на **https://developers.facebook.com**.
2. Войдите под аккаунтом Facebook, который связан с вашим Instagram Business/Creator-аккаунтом.
3. В верхнем меню нажмите **My Apps** → **Create App**.
4. В списке типов выберите **Other** (Другое) → нажмите **Next**.
5. На следующем экране выберите тип **Business** → нажмите **Next**.
6. Введите любое название приложения (например, `Reels Report Bot`) и нажмите **Create app**.

### 1.2. Добавить продукт Instagram

7. После создания вы окажетесь на панели приложения. Найдите раздел **Add products to your app** (Добавить продукты).
8. Найдите карточку **Instagram** и нажмите **Set up**.
9. В открывшемся разделе Instagram выберите **API setup with Instagram business login** (Настройка API с входом через Instagram).

### 1.3. Сгенерировать токен

10. Прокрутите страницу до раздела **Generate access tokens**.
11. Нажмите **Add Instagram account** и выберите ваш Instagram Business или Creator-аккаунт.
12. В диалоге разрешений убедитесь, что выбраны оба разрешения:
    - `instagram_business_basic`
    - `instagram_business_manage_insights`
13. Нажмите **Confirm** / **Разрешить**.
14. После подтверждения вернитесь в раздел **Generate access tokens** → нажмите **Generate token** рядом с вашим аккаунтом.
15. Скопируйте появившийся **долгоживущий токен** (Long-lived token, действует 60 дней). Сохраните его — это значение переменной `IG_ACCESS_TOKEN`.

> **Примечание:** бот автоматически продлевает токен каждый день после деплоя — вам достаточно вставить его один раз.

### 1.4. Скопировать Instagram User ID

16. Там же, под вашим аккаунтом, отображается **Instagram User ID** (числовой идентификатор, например `17841400000000000`).
17. Скопируйте его — это значение переменной `IG_USER_ID`.

## Шаг 2. Получение ID группового чата Telegram

> Предполагается, что у вас уже есть Telegram-бот и его токен от @BotFather. Токен выглядит как `1234567890:ABC...` — это значение переменной `TELEGRAM_BOT_TOKEN`.

### 2.1. Добавить бота в группу

1. Откройте Telegram, найдите нужный групповой чат.
2. Войдите в настройки группы → **Добавить участника** (Add Member).
3. Найдите вашего бота по имени и добавьте его в группу.
4. Дайте боту права **Send Messages** (отправка сообщений) — обычно это включено по умолчанию.

> **Важно:** если группа является супергруппой или каналом, сделайте бота администратором с правом отправки сообщений — без этого бот не сможет писать в чат.

### 2.2. Узнать ID чата

5. Отправьте в группу команду `/start@имя_вашего_бота` (например, `/start@MyReelsBotReportBot`). Именно команду с упоминанием бота — если включён режим приватности, обычные сообщения не попадают в getUpdates.
6. Откройте в браузере следующую ссылку, подставив токен вашего бота:

   ```
   https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates
   ```

   Пример: `https://api.telegram.org/bot1234567890:ABC.../getUpdates`

7. В ответе найдите объект `"chat"` → поле `"id"`. Для групп это **отрицательное число**, например `-1001234567890`.
8. Скопируйте это число — это значение переменной `TELEGRAM_CHAT_ID`.

> **Если список пустой:** отправьте `/start@имя_вашего_бота` ещё раз и обновите страницу.

## Шаг 3. Деплой на Vercel

### 3.1. Установить Vercel CLI и привязать проект

1. Откройте терминал и выполните:

   ```bash
   npm i -g vercel@latest
   ```

2. Перейдите в папку проекта:

   ```bash
   cd /путь/к/папке/qurany
   ```

3. Привяжите проект к Vercel:

   ```bash
   vercel link
   ```

   Следуйте подсказкам: войдите в аккаунт Vercel (откроется браузер), выберите организацию, создайте новый проект или привяжите существующий.

### 3.2. Создать Blob-хранилище

4. Откройте браузер и перейдите в **https://vercel.com/dashboard** → найдите ваш проект → нажмите вкладку **Storage**.
5. Нажмите **Create** → выберите **Blob** → нажмите **Create**.
6. На экране подключения выберите ваш проект и нажмите **Connect**.
7. Vercel автоматически добавит переменную `BLOB_READ_WRITE_TOKEN` в окружение проекта — ничего копировать не нужно.

### 3.3. Добавить переменные окружения

Выполните в терминале следующие команды **по одной**, подставив ваши реальные значения:

```bash
vercel env add IG_ACCESS_TOKEN production
```
*(введите токен Instagram из раздела 1, шага 1.3 и нажмите Enter)*

```bash
vercel env add IG_USER_ID production
```
*(введите Instagram User ID из раздела 1, шага 1.4 и нажмите Enter)*

```bash
vercel env add TELEGRAM_BOT_TOKEN production
```
*(введите токен Telegram-бота и нажмите Enter)*

```bash
vercel env add TELEGRAM_CHAT_ID production
```
*(введите ID группового чата из раздела 2, шага 2.2, включая знак минус, и нажмите Enter)*

Сгенерируйте случайный секрет для защиты ручного запуска:

```bash
openssl rand -hex 32
```

Скопируйте вывод (64 символа) и выполните:

```bash
vercel env add CRON_SECRET production
```
*(вставьте сгенерированную строку и нажмите Enter)*

Сохраните значение `CRON_SECRET` — оно понадобится в разделе «Шаг 4. Проверка работы».

### 3.3a. Переменные для секции «Таргет» (реклама + уровни лидов)

Нужны для суточной секции таргета в отчёте и команд `/target` и `/targettotal`.
Если их не задать — отчёт по рилсам продолжит работать, а секция таргета просто
не отправится (ошибка изолирована).

**Meta Marketing API** (рекламные цифры: потрачено, показы, клики, охват, лиды, цена за результат):

```bash
vercel env add META_AD_ACCOUNT_ID production
```
*(ID рекламного аккаунта, вида `act_1234567890` или просто `1234567890`)*

```bash
vercel env add META_ADS_TOKEN production
```
*(access-токен с правом `ads_read`; лучше — долгоживущий токен system-user из Business Manager)*

Необязательные:
- `META_LEAD_ACTION_TYPE` — закрепить точный тип результата-лида (напр. `offsite_conversion.fb_pixel_lead`), если авто-выбор берёт не тот. По умолчанию выбирается самый специфичный `*lead*`.
- `META_CURRENCY` — валюта на случай, если Insights не вернёт `account_currency` (по умолчанию `USD`).

**Supabase** (разбивка лидов по уровню инвестора — те же значения, что у квиза pilar-qurany):

```bash
vercel env add SUPABASE_URL production
```
```bash
vercel env add SUPABASE_SERVICE_ROLE_KEY production
```
*(возьмите те же значения, что в проекте квиза pilar-qurany — читаем таблицу `leads`)*

### 3.4. Запустить деплой

```bash
vercel --prod
```

Дождитесь сообщения `Production: https://<project>.vercel.app`. Скопируйте URL проекта.

## Шаг 4. Проверка работы

### 4.1. Ручной запуск первого отчёта

Выполните в терминале, заменив `<CRON_SECRET>` на значение из шага 3.3 и `<project>` на имя вашего проекта на Vercel:

```bash
curl -H "Authorization: Bearer <CRON_SECRET>" \
  https://<project>.vercel.app/api/report
```

Пример:
```bash
curl -H "Authorization: Bearer a1b2c3d4e5f6..." \
  https://reels-report-bot.vercel.app/api/report
```

### 4.2. Что должно произойти

- В Telegram-группу придёт сообщение **«📊 Отчёт по рилсам»** с пометкой «Это базовый замер».
- Это нормально: первый запуск сохраняет базовую точку отсчёта. Прирост за сутки появится в **завтрашнем отчёте**.
- Таблица (CSV) со всеми рилсами больше не приходит автоматически — запросите её командой **/otchet** (см. ниже).

### 4.3. Автоматический крон

После деплоя бот будет автоматически запускаться **каждый день в 12:30 по времени Джакарты (WIB)** без каких-либо дополнительных действий с вашей стороны.

## Команды бота в Telegram

Прямо в группе можно написать боту:

- **/now** — отчёт с 12:30 вчера (последний ежедневный замер) по текущий момент — сколько видео выпущено, сколько просмотров набрано, сколько подписчиков прибавилось.
- **/otchet** — CSV-таблица со всеми рилсами (ссылки, просмотры, прирост), отсортированная по приросту; строки 1–10 = ТОП-10.
- **/info** — общая статистика: подписчики, сколько всего рилсов, тотал просмотров, среднее на рилс, лучший рилс, дата последней публикации.
- **/nowapp** и **/infoapp** — то же самое, но по второму аккаунту @qurany_app (см. раздел «Второй аккаунт»).

Ежедневный отчёт также показывает подписчиков: сколько сейчас, прирост за период и сколько подписалось/отписалось за тот же период (по данным Instagram). Это отдельная валовая метрика Instagram, и её разница (подписалось минус отписалось) может не совпадать с чистым приростом: Instagram досчитывает свежие данные с задержкой и не относит к «отпискам» удалённые/заблокированные аккаунты. Ориентируйтесь на чистый прирост.

> ⚠️ После добавления команды **/otchet** один раз перезапустите настройку вебхука (`GET /api/report`… → раздел 3 «Регистрация вебхука», запрос `GET /api/telegram` с `Authorization: Bearer <CRON_SECRET>`), чтобы она появилась в меню команд Telegram.

Бот отвечает в ту же тему (вкладку) группы, где написана команда. Данные берутся из Instagram в момент запроса — ответ может занять несколько секунд.

Команды работают через Telegram-webhook. После первого деплоя (или смены домена) webhook нужно зарегистрировать один раз — бот настроит его сам:

```bash
curl "https://<ваш-домен>/api/telegram" -H "Authorization: Bearer <CRON_SECRET>"
```

## Если токен Instagram истёк

Долгоживущий токен действует 60 дней, но бот продлевает его автоматически при каждом ежедневном запуске. Если токен всё же истёк (бот напишет сообщение о недействительном токене):

1. Получите новый токен по инструкции из **раздела 1** (шаги 1.3–1.4).
2. Обновите переменную `IG_ACCESS_TOKEN` в Vercel:
   - Через дашборд: **https://vercel.com/dashboard** → ваш проект → **Settings** → **Environment Variables** → найдите `IG_ACCESS_TOKEN` → **Edit** → вставьте новый токен.
   - Через CLI: `vercel env add IG_ACCESS_TOKEN production` (введите новый токен).
3. Задеплойте заново: `vercel --prod`.

Бот автоматически подхватит новый токен при следующем запуске — повторно настраивать ничего не нужно.

## Ферма рилсов

### Что это такое

Ферма рилсов — отдельный конвейер поверх того же бота: команда `/batch` в чате отдаёт ссылку на страницу загрузки пачки подложек и текстов. На странице загружается пачка видео-подложек и один текстовый файл, где блоки разделены строкой `---`; первая строка каждого блока — хук (короткая фраза на индонезийском), остальные строки — описание к посту. Бот прогоняет каждую подложку через ffmpeg, вжигает в кадр хук и присылает получившийся ролик в чат с кнопками **[Залить]**, **[Выкинуть]**, **[Текст]**. Одобренные ролики сами уходят публикацией в Trial Reels аккаунта @daristeppe по расписанию слотов — вручную ничего заливать не нужно.

Команда `/reels` показывает текущее состояние фермы (сколько роликов ждёт модерации, сколько запланировано, сколько уже залито) и, если цепочка рендера где-то оборвалась, сама её подталкивает дальше.

### Токен публикации

*(Это отдельный токен, а не `IG_ACCESS_TOKEN` отчётного бота: ферма публикует через `graph.facebook.com` по Facebook Login, а отчётный бот читает статистику через `graph.instagram.com`. Путать их нельзя — токен одного API не подойдёт для другого.)*

1. Откройте **Graph API Explorer** (developers.facebook.com/tools/explorer), выберите приложение фермы.
2. Запросите права: `instagram_basic`, `instagram_content_publish`, `pages_show_list`, `pages_read_engagement`, `business_management`.
3. Получите короткоживущий **User Token**.
4. Обменяйте его на 60-дневный:

   ```bash
   curl -s "https://graph.facebook.com/v23.0/oauth/access_token?grant_type=fb_exchange_token&client_id=$FARM_FB_APP_ID&client_secret=$FARM_FB_APP_SECRET&fb_exchange_token=$SHORT_TOKEN"
   ```

5. По полученному долгоживущему пользовательскому токену получите список страниц с их Page-токенами:

   ```bash
   curl -s "https://graph.facebook.com/v23.0/me/accounts?fields=name,access_token,instagram_business_account&access_token=$LONG_TOKEN"
   ```

6. Возьмите `access_token` той страницы, у которой `instagram_business_account.id` равен `FARM_IG_ID`. Для @daristeppe это `17841413773053161`, связанная страница Facebook называется «Видео из Фото». Именно этот Page-токен кладётся в переменную `FARM_IG_TOKEN` — в отличие от пользовательских токенов, Page-токен не истекает вовсе.

*(App Review проходить не нужно, пока публикация идёт на собственный аккаунт под ролью администратора приложения. Суточная уборка `/api/farm/daily` сама проверяет токен и предупредит в чат, если он отозван или истекает менее чем через 7 дней.)*

### Переменные окружения фермы

```bash
vercel env add FARM_TOKEN_SECRET production
```
*(HMAC-секрет для подписи ссылки загрузки, тиков рендера и внешнего таймера заливки — сгенерируйте `openssl rand -hex 32`)*

```bash
vercel env add FARM_IG_TOKEN production
```
*(Page-токен из раздела «Токен публикации», шаг 6 — не путать с `IG_ACCESS_TOKEN`)*

```bash
vercel env add FARM_IG_ID production
```
*(ID Instagram Business-аккаунта фермы, для @daristeppe — `17841413773053161`)*

```bash
vercel env add FARM_FB_APP_ID production
```
*(App ID приложения фермы на developers.facebook.com)*

```bash
vercel env add FARM_FB_APP_SECRET production
```
*(App Secret того же приложения)*

Необязательные (есть значения по умолчанию):

- `FARM_SLOT_START` — время первого слота публикации за день (по умолчанию `09:00`).
- `FARM_SLOT_MINUTES` — интервал между слотами в минутах (по умолчанию `45`).
- `FARM_SLOTS_PER_DAY` — сколько слотов публикации в сутки (по умолчанию `15`).
- `FARM_TZ` — таймзона расписания слотов (по умолчанию `Asia/Jakarta`).
- `FARM_BASE_URL` — базовый URL для само-вызова цепочки рендера (по умолчанию `https://$VERCEL_PROJECT_PRODUCTION_URL`).
- `FARM_FONT_PATH` — путь к ttf-файлу, которым ffmpeg вжигает хук в кадр; по умолчанию `assets/hook.ttf` в корне бандла. Способ подменить шрифт, не заменяя файл в репозитории.

### Внешний таймер заливки

Vercel Hobby даёт только 2 крона на проект, и оба — с суточным расписанием; варианта «каждые 15 минут» на Hobby-плане нет. Поэтому заливку одобренных роликов по слотам дёргает внешний таймер — **cron-job.org** (или UptimeRobot) — раз в 15 минут запросом:

```
GET https://<домен>/api/farm/post?key=<ключ>
```

Ключ считается из `FARM_TOKEN_SECRET`: подставьте значение секрета прямо в команду (возьмите его через `vercel env pull` или из того, что сгенерировали `openssl rand -hex 32`), иначе `process.env.FARM_TOKEN_SECRET` в чистой оболочке окажется пустым и команда упадёт с `ERR_INVALID_ARG_TYPE`.

```bash
FARM_TOKEN_SECRET='<значение из vercel env>' node -e "console.log(require('crypto').createHmac('sha256', process.env.FARM_TOKEN_SECRET).update('tick.post').digest('base64url'))"
```

*(Ключ в URL безопасен по последствиям: чужой запрос с этим ключом способен максимум запустить заливку уже одобренных роликов по их же расписанию слотов — ничего нового он одобрить или залить раньше времени не может.)*

### Суточный крон `/api/farm/daily`

Уже прописан в `vercel.json` на 20:00 UTC. Каждый день он убирает старые временные файлы, снимает застрявшие задачи рендера, удаляет осиротевшие подложки без пары, проверяет срок действия `FARM_IG_TOKEN` и добирает просроченные слоты публикации.

> ⚠️ После добавления этого крона **оба** слота, доступных на Hobby-плане, заняты: первый — отчёт `/api/report` в 5:45 UTC, второй — `/api/farm/daily` в 20:00 UTC. Запаса под третий крон не осталось.

### Шрифт хука

`assets/hook.ttf` — жирный sans-шрифт с латиницей, которым ffmpeg вжигает хук в кадр подложки. Файл лежит прямо в репозитории и попадает в бандл роута рендера через `outputFileTracingIncludes` в `next.config.ts`. Заменить шрифт — значит просто заменить этот файл на другой `.ttf` с тем же именем.

Сам шрифт — Montserrat Bold, лицензия SIL Open Font License 1.1, её полный текст лежит в `assets/hook.ttf.LICENSE.txt`. При замене шрифта на другой рядом нужно класть его собственную лицензию.

## График воронки за 14 дней

Картинка после отчёта по аккаунту — три этажа на общей оси дней, сверху вниз:

| Этаж | Что на нём | Откуда данные |
|------|-----------|---------------|
| Вход | ролики, вышедшие за сутки (столбики) | даты публикации из снапшотов окна, склеенные по id (`computeDailyPublished`) |
| Середина | прирост просмотров за сутки | разница тотала между соседними снапшотами (`computeDailyViewGains`) |
| Выход | заходы в сообщество по ссылке аккаунта | PostHog, условие `clicksCondition` аккаунта |
| Выход | переходы в стор `/go/<слаг>` | записи кликов в Blob, слаги `storeSlugs` аккаунта |

Без входа средний этаж не читается: непонятно, просмотры выросли потому что контент лучше, или потому что роликов стало больше.

Сутки у всех этажей одни и те же — от 12:30 Джакарты до 12:30, как у самого отчёта; день называется по моменту закрытия (`sprintDateKey`). Ноль на линии выхода — это факт «переходов не было», а разрыв — «источника нет»: у аккаунта не заполнен `clicksCondition` или `storeSlugs` в `lib/accounts.ts`.

Ролики склеиваются по id из всех снапшотов окна, а не берутся из свежего: иначе удалённый (или снятый Instagram) ролик задним числом укоротил бы столбик того дня, когда он вышел.

Каждому этажу нужна своя шкала (5 роликов и миллион просмотров на одной оси — прямая по нулю), поэтому конфиг требует Chart.js v4 со stacked-шкалами. Условные подписи Chart.js умеет только функциями, поэтому конфиг уезжает в QuickChart строкой с JS: нулевые значения не подписываются, а нижнее деление верхних этажей снимается — этажи стоят вплотную и делят одну колонку подписей (см. метки в `lib/chart.ts`).

Новую дверь в стор (нового амбассадора, новую воронку) видно на графике только после того, как её слаг добавлен в `storeSlugs` нужного аккаунта; в общей сводке «Переходы в стор» она появится сама.

## Второй аккаунт: @qurany_app

Бот ведёт отчётность по нескольким аккаунтам Instagram сразу. Список аккаунтов — в `lib/accounts.ts`; всё, что их различает (переменные, файлы в хранилище, вкладки таблицы, подпись в сообщениях), собрано там.

Что приходит в 12:30 по каждому аккаунту: отчёт по рилсам с подписью аккаунта в заголовке, график воронки за 14 дней и обновление своих вкладок Google-таблицы. Сводки по заходам и таргету общие для проекта и приходят один раз, без разбивки по аккаунтам.

Чтобы подключить аккаунт, нужны две переменные (для @qurany_app — уже заданы):

```bash
vercel env add IG_USER_ID_QURANY_APP production      # 17841444197238385
vercel env add IG_ACCESS_TOKEN_QURANY_APP production # токен из шага 1.3, выпущенный под этим аккаунтом
```

Токен выпускается так же, как в шаге 1.3, но входить в Instagram надо именно под @qurany_app (аккаунт должен быть принят как Instagram tester в приложении Meta). Дальше бот продлевает его сам при каждом ежедневном запуске, как и токен первого аккаунта, — 60-дневный срок обновляется, пока крон ходит.

Если переменных нет, аккаунт просто пропускается: отчёт по остальным аккаунтам от этого не страдает. Так же и при сбое — упавший Instagram по одному аккаунту не отменяет отчёт по второму.

Полезное для проверки (Bearer `CRON_SECRET`):

```bash
# отчёт только по одному аккаунту: без дедупликации и без общих сводок,
# то есть не съедает дневной запуск и не дублирует клики/таргет
curl "https://<домен>/api/report?only=qurany-app&force=1" -H "Authorization: Bearer <CRON_SECRET>"

# обновить только Google-таблицу по аккаунту (?dry=1 — посчитать, но не писать)
curl "https://<домен>/api/sheet?account=qurany-app" -H "Authorization: Bearer <CRON_SECRET>"
```

В ответе `/api/report` по каждому аккаунту видно, что стало с графиком и таблицей (`chart`, `sheet`): их ошибки намеренно не роняют отчёт, поэтому единственный способ заметить сбой — этот ответ и логи Vercel.

Первый день по новому аккаунту — базовый замер: прирост появится в завтрашнем отчёте, линия просмотров на графике — через день, вкладка History начнёт копить дни с первого замера (за прошлое Instagram данных по дням не отдаёт).

> ⚠️ После добавления команд **/nowapp** и **/infoapp** один раз перезапустите регистрацию вебхука (`GET /api/telegram` с `Authorization: Bearer <CRON_SECRET>`), чтобы они появились в меню команд Telegram.
