# Telegram-бот для вшивания индонезийских субтитров

Бот принимает видео с русской речью и должен возвращать тот же ролик со вшитыми
индонезийскими субтитрами. Полная архитектура — в дизайн-документе:
`docs/superpowers/specs/2026-08-20-telegram-subtitle-bot-design.md`.

## Текущее состояние

Это переименованный `dub-bot/` (дубляж через ElevenLabs Dubbing API, ни разу не
задеплоен): дубляжная середина вырезана, остался только каркас. Пайплайн
распознавания, перевода и вшивания субтитров (Scribe → перевод → утверждение →
ffmpeg/libass) ещё не реализован — это последующие задачи по плану
`docs/superpowers/plans/2026-08-20-telegram-subtitle-bot.md`.

Что уже работает:

- вебхук Telegram (`POST /api/telegram`) с командами `/sub`, `/status`, `/help`;
- страница загрузки по подписанному токену (`app/u/[token]/`) — браузер грузит
  файл напрямую в Vercel Blob, минуя лимиты Telegram;
- создание задачи (`lib/start.ts`) — проверка токена, проверка владения blob,
  запись задачи в Blob со статусом `pending`;
- суточная уборка (`GET /api/cleanup`) — закрывает зависшие задачи и чистит
  файлы завершённых.

Чего пока нет: обработки задачи после создания (распознавание речи, перевод,
рендер субтитров) и HTTP-роута, который бы `startJob` из `lib/start.ts`
вызывал — его создаст задача, реализующая конвейер обработки.

## Архитектура

Ключевая особенность (унаследована от `dub-bot` без изменений): **видео не
загружается через бота**. Telegram ограничивает загрузку 20 МБ на скачивание и
50 МБ на отправку, а исходные ролики тяжелее.

Вместо этого:

1. Пользователь отправляет `/sub` боту.
2. Бот возвращает ссылку на страницу загрузки (действительна 30 минут).
3. Пользователь открывает ссылку в браузере и выбирает видео из галереи.
4. Браузер загружает файл напрямую в Vercel Blob (без ограничений размера).
5. Дальнейшая обработка и доставка результата в Telegram — предмет
   последующих задач.

## Команды бота

- **`/sub`** — получить ссылку для загрузки видео. Ссылка действует 30 минут.
- **`/status`** — показать активные задачи (`pending`, `delivering`).
- **`/help`** — справка.

## Переменные окружения

Все переменные обязательны.

| Переменная | Откуда | Назначение |
| --- | --- | --- |
| `TELEGRAM_SUB_BOT_TOKEN` | @BotFather | Токен бота Telegram. |
| `TELEGRAM_ALLOWED_CHAT_IDS` | ручная | Список chat_id, через запятую. Только эти чаты могут использовать бота. |
| `TELEGRAM_WEBHOOK_SECRET` | ручная (криптографический) | Секрет для проверки вебхука Telegram (`setWebhook`). Генерируется `openssl rand -hex 32`. |
| `SUB_TOKEN_SECRET` | ручная (криптографический) | Секрет для подписи токенов загрузки (HMAC). Генерируется `openssl rand -hex 32`. |
| `SUB_BASE_URL` | ручная | Прод-URL проекта. Добавляется после первого деплоя. |
| `CRON_SECRET` | ручная (криптографический) | Секрет cron-задачи очистки. Обязателен: без него `/api/cleanup` отвечает ошибкой, а не работает без проверки. Генерируется `openssl rand -hex 32`. |
| `BLOB_READ_WRITE_TOKEN` | Vercel | Выдаётся Vercel автоматически при подключении Blob Storage. |

Переменные под сам конвейер обработки (`ELEVENLABS_API_KEY` для Scribe,
`OPENAI_API_KEY` для перевода и пути к бинарникам ffmpeg/шрифту) появятся вместе
с задачей, которая их использует — см. дизайн-документ.

## Подключение вебхука Telegram

После деплоя нужно подключить вебхук для получения сообщений:

```bash
curl -sS -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{
    "url":"https://<домен>/api/telegram",
    "secret_token":"<TELEGRAM_WEBHOOK_SECRET>",
    "allowed_updates":["message"]
  }'
```

Заменить:
- `<ТОКЕН>` → значение `TELEGRAM_SUB_BOT_TOKEN`
- `<домен>` → прод-URL проекта
- `<TELEGRAM_WEBHOOK_SECRET>` → значение переменной окружения

Проверить статус:

```bash
curl -sS "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

Должны увидеть:
- `"url"` совпадает с установленной ссылкой
- `"last_error_message"` отсутствует или пустой
